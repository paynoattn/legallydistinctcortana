# Lessons from poteto, as gates

Lauren Tan ([poteto](https://x.com/poteto)) worked on React (core team, React Compiler) at Meta, fixed performance on Cursor's agents window, and now leads Grok Bot at SpaceX AI. This page collects what she said about building codebases that agents cannot get wrong, and names the gate in [`react-vite-ts`](../../) that enforces each point. Same rule as [`principles.md`](principles.md): a lesson without a gate is a guideline.

## The order of defenses

> "Either invest the time to make that pattern categorically impossible through your code base and architecture and data structures, or you start looking at things like static analysis, and then you layer that on with rules and bug bot and skills." [X 00:36:52]

Her ladder, strongest first: the codebase makes the mistake impossible, then lint, compiler, and CI, then rules and skills, then a human style guide. It is the same ladder as the `encode-rule` skill and Uncle Bob's "gates over guidance" ([`principles.md`](principles.md) §1). The starter applies it like this:

## Not encoded

- **Feature maps and verification skills** for a large app (her `create-verification-skill`, [`verification-skill-example`](https://github.com/poteto/verification-skill-example)). A one-screen starter does not need one; add it when the app grows past what `qa/procedures` can describe.
- **Outer loops, routines, and auto-merge.** These are about the team's workflow, not the codebase.
- **Gardening.** Sampling merged code and turning repeated mistakes into rules is a human or agent routine. The `encode-rule` skill is the hook for it.
