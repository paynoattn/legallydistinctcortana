# 014. Voice activity detection (Silero)

| Milestone    | Size | Depends on | Labels                                   |
| ------------ | ---- | ---------- | ---------------------------------------- |
| M1 Dictation | S    | #013       | area/voice, area/inference, type/feature |

## Story

As a dictating user, I want the assistant to know when I am speaking and when I have stopped, so that toggle mode can stop on its own and silence is never sent to the speech model.

## Context

[Voice: dictation pipeline](../architecture/voice-and-speech.md#dictation-pipeline): ring buffer → Silero VAD (in-process, ONNX Runtime CPU, about 1 ms per frame) → segments → infer-host STT. Toggle mode has optional VAD auto-stop. [ADR 0007](../architecture/adr/0007-model-runtimes.md): Silero VAD on ONNX Runtime CPU. The installer ships the VAD model.

## Scope

- `voice-domain`: `VadSegmenter`, a pure state machine over per-frame speech probabilities: speech start after 60 ms above the start threshold (default 0.5), speech end after a configurable silence (default 700 ms below 0.35), with 200 ms padding kept on both sides. It emits `SpeechStarted`, `SpeechEnded`, and `Segment { start, end }`.
- `voice-application`: a `SpeechProbability` port (`frame -> f32`), and wiring so the dictation session gets segments and an auto-stop signal.
- Infrastructure adapter running Silero VAD in process on the CPU, loading the model from the app's resources with its SHA-256 checked at load.
- Settings (shared): `voice.toggle_auto_stop` (bool, default on), `voice.auto_stop_silence_ms` (400–3000, default 1200 for toggle auto-stop).

Out of scope: wake word (#057), noise suppression, STT itself (#016).

## Acceptance criteria

`features/core/vad.feature` with recorded fixtures (short WAV files in `features/core/fixtures/`) and the real adapter behind the `slow` feature; the segmenter is property-tested with synthetic probabilities.

```gherkin
Feature: Voice activity detection

  Scenario: Speech between silences becomes one segment
    Given the fixture "hello-world-with-silence.wav"
    When it is run through VAD
    Then exactly one segment is produced covering the spoken words with 200 ms padding

  Scenario: Toggle mode stops after silence
    Given toggle mode with auto-stop after 1200 ms of silence
    When the user says one sentence and stays silent
    Then the session moves to Finalizing about 1.2 s after the last word

  Scenario: Pure silence produces nothing
    Given 5 seconds of room noise
    Then no segment is produced and STT is not called

  Scenario: The VAD model is missing or corrupt
    Given the VAD model file fails its SHA-256 check
    When dictation is armed
    Then the session still records in push-to-talk mode without auto-stop
    And the overlay error says "Voice detection unavailable: reinstall or repair the app"

  Scenario: A cough does not start speech
    Given a 40 ms burst above the start threshold
    Then no SpeechStarted is emitted
```

## Design notes

- Placement per [ADR 0007](../architecture/adr/0007-model-runtimes.md): Silero runs in process in `voice-infrastructure` on ONNX Runtime (`ort`) with the CPU execution provider only, so there is no IPC hop per frame and VAD keeps working when `infer-host` is stopped. `ort` is allowed in `voice-infrastructure` and `infer-host` only.
- `arch.toml`: `voice-domain` allow `["kernel"]`; `voice-infrastructure` allow `["voice-application", "voice-domain", "platform-ports", "kernel", "store"]`, ban `tauri`. Verify how `ort` is linked (prebuilt ONNX Runtime download at build time or a bundled DLL) and that the same ONNX Runtime DLL can be shared with `infer-host` without version clashes.
- Silero VAD is MIT-licensed (verify the model file's license as well as the code's). Its 16 kHz model expects fixed chunk sizes (verify: 512 samples for v5), so the adapter re-chunks the 320-sample frames.
- Budget: under 1 ms per 20 ms frame on a mid-range CPU, measured in the `bench` job (#077), not in `make check`.
- Privacy: audio stays in memory; only segment timings are logged.

## QA procedure

1. Set dictation to toggle mode with auto-stop on. Start, say "testing one two three", and wait. Dictation stops by itself in about a second.
2. Start toggle mode and say nothing for 10 seconds, then stop. No text is inserted and the overlay shows no error.
3. Start push-to-talk, cough once, and release. No text is inserted.
4. Rename the VAD model file in the install folder and restart. Push-to-talk still works; toggle auto-stop is disabled and the overlay explains why. Restore the file.
5. With Task Manager open, hold push-to-talk for 30 seconds. CPU use from VAD stays low (well under one core).
